# Developer

The Developer space records gaps between Jue's target architecture and current
implementation. It is for maintainers and implementation agents, not a
prerequisite for ordinary users.

## Reading order

1. [Architecture](../architecture/) for stable principles.
2. [Documentation Contract](documentation-contract.md) for precedence.
3. [Implementation Status](implementation-status.md) for current gaps.
4. [Roadmap](roadmap.md) for dependency-ordered delivery.
5. [Delivery Plan](delivery-plan.md) to claim work and submit evidence.
6. [Claude Code Execution Runbook](claude-code-execution.md) for dependency-aware
   decomposition, parallel implementation, and verification.
7. [RFCs](rfcs/) for proposals and decisions.

## Documentation boundary

| Space | Question |
| --- | --- |
| Guide | How does a user complete a task? |
| Architecture | Why is Jue designed this way? |
| Reference | What is the ideal complete contract? |
| Developer | How far is implementation from that contract, and what comes next? |

Unimplemented Reference contracts remain normative and link here for status.
Completing a feature requires synchronized implementation, tests, Agent support
profiles, status, and Delivery Plan.
